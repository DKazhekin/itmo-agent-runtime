# Реальная модель и ограничение расходов

Модель вызывается отдельным HTTPS-посредником. Ключ поставщика получает только `llm-proxy`; управляющий цикл, клиент и песочница его не получают. По умолчанию сервер и клиент используют `mock`: заранее заданные ответы проверяют инфраструктуру, а не качество модели.

## Параметры записанного эксперимента

| Параметр | Значение |
| --- | --- |
| Модель OpenRouter | `deepseek/deepseek-v4.1-flash-1017` |
| Версия | `deepseek-v4.1-flash-20261017` |
| Режим рассуждения | `high` |
| Поставщик | DeepInfra, адрес `deepinfra/fp8` |
| Точность | FP8, восьмибитный формат с плавающей запятой |
| Маршрутизация | Только указанный адрес, без автоматического перехода к другому поставщику |
| Использование данных | `data_collection: "deny"` |
| Индекс Artificial Analysis | 29, версия индекса 5.0.1, проверка 2026-11-06 |
| Полный успешный прогон | 15/15 задач, без пропусков |

DeepSeek 4.1 прямо разрешён [закреплёнными требованиями курса](https://github.com/deeppavlov/agentic-course-itmo/blob/b01ddf7b89e5c603985e3d5b5af958bebc7b1972/projects/README.md). Значение 29 относится к [режиму high](https://artificialanalysis.ai/models/deepseek-v4-1-flash-1017-high); результат режима max этому эксперименту не приписывается. Доступность адреса, условия поставщика и значения индекса могут измениться; для нового эксперимента их проверяют заново.

[Успешная попытка](../../evidence/baf/real/20261106T125440Z-e6a11cdd/summary.json) содержит 216 720 входных и 13 955 выходных токенов; сумма длительностей задач — 183,513 секунды. Файловые проверки и подтверждение исполнения команд Б5 прошли. Это один успешный полный прогон, а не оценка вероятности успеха по серии независимых повторов.

Все четыре попытки опубликованы:

| Попытка | Результат |
| --- | --- |
| [Первое подключение](../../evidence/baf/real/20261106T124427Z-beceee4d/summary.json) | 0/1: ошибка подключения к первоначальному адресу поставщика |

Между полными прогонами инструкция уточнила, что `RunCommand` возвращает отдельные stdout, stderr и exit code, а существующие программы следует запускать непосредственно. Подсказки ответов конкретных заданий не добавлялись; исходные задания и независимые проверки не менялись. [Сохранённая проверка результата](../../evidence/verification/real-run-audit.json) подтвердила 322 события по схеме и неизменность заданий между этими прогонами. Исторические хеши относятся к состоянию кода во время эксперимента.

Общая стоимость всех попыток по метаданным OpenRouter составила **0,018821183 доллара США**. Это наблюдение конкретного эксперимента, а не прогноз цены нового запуска. Сводные результаты и правила представления опубликованных копий находятся в [наборе доказательств](../../evidence/README.md).

## Подготовка нового эксперимента

Сначала выполните [обычную подготовку](environment.md) и оставьте сервер в режиме `mock`. Укажите в локальном `.env`:

```dotenv
MODEL_MODE=mock
MODEL_BASE_URL=https://openrouter.ai/api/v1
MODEL_NAME=deepseek/deepseek-v4.1-flash-1017
MODEL_API_KEY=<your-provider-key>
MODEL_BUDGET_ID=<one-id-for-the-experiment>
MODEL_BUDGET_USD=<total-limit-in-usd>
```

Угловые скобки обозначают значения, которые требуется заменить. `MODEL_BUDGET_USD` — положительное десятичное число; идентификатор и общий предел одинаковы для всех попыток одного эксперимента. Повторный запуск не создаёт новый бюджет. `.env` исключён из Git; ограничьте доступ к нему:

```sh
chmod 600 .env
sh scripts/compose.sh up -d --build --wait
```

Настройка другого HTTPS-поставщика технически возможна, но автоматическая денежная граница реализована только для описанного профиля OpenRouter. Гарантии этого профиля нельзя переносить на произвольную модель или адрес.

### Сведения о модели

Создайте локальную копию примера:

```sh
mkdir -p .local
cp examples/model-evidence.json .local/model-evidence.json
```

В [примере](../../examples/model-evidence.json) поле `approval` пустое, а `budget_limit` равно нулю: файл намеренно не готов для платного запуска. До использования заполните:

- `model` и `version`: точный идентификатор и версия модели; для текущего ограничителя используется закреплённая модель из таблицы выше.
- `index` и `index_date`: проверенные значение индекса и дата в формате `YYYY-MM-DD`; обновите ссылку на источник и обоснование допуска.
- `access`: способ доступа и поставщик без ключа или других секретов.
- `approval`: запись о разрешённом расходе на этот эксперимент, без личных данных.
- `budget_limit`: фактический общий предел, совпадающий с `MODEL_BUDGET_USD`.

Запускатель проверяет форму этих данных и сохраняет их в манифесте попытки. Само наличие `approval` не удостоверяет полномочия, а `budget_limit` не ведёт учёт денег. Расходы ограничивает отдельный постоянный журнал.

### Однократная инициализация журнала

При `MODEL_MODE=mock` и уже заданных идентификаторе и лимите выполните **один раз для нового эксперимента**:

```sh
sh scripts/compose.sh exec -T llm-proxy python -c 'import os; from runtime.budget import BudgetLedger; BudgetLedger("/model-state/budget.sqlite3", os.environ["MODEL_BUDGET_ID"], os.environ["MODEL_BUDGET_USD"])'
```

База находится в именованном томе `model-state`. Рабочий процесс в режиме `real` открывает только существующий журнал и существующий идентификатор. Лимит неизменяем для этого идентификатора. Отсутствующий или удалённый журнал приводит к отказу запроса, а не к созданию нового нулевого баланса.

Перед первым платным вызовом проверьте условия и доступность выбранного адреса OpenRouter, доступные сведения об оплате и отсутствие применимого собственного ключа внешнего поставщика. Такой режим называется BYOK (bring your own key): оплата внешнему поставщику не входит в границу кредитов OpenRouter. Нулевой прежний расход BYOK сам по себе не доказывает отсутствие такого ключа; каждый ответ дополнительно проверяется по `usage.is_byok`.

### Запуск

После заполнения сведений и инициализации журнала измените в `.env` только `MODEL_MODE=real`, затем примените конфигурацию:

```sh
sh scripts/compose.sh up -d --wait
curl --fail http://127.0.0.1:8080/health
```

Готовность должна показывать `model_mode: "real"` и точный идентификатор модели. Проверка готовности не вызывает генерацию. Если `CLIENT_TOKEN` изменён в `.env`, задайте тот же `CLIENT_TOKEN` в окружении клиентской команды: клиент не загружает `.env` автоматически.

Проверка одной задачи:

```sh
.venv/bin/python -m baf.run --mode real   --model-evidence .local/model-evidence.json --task B1.1
```

Все 15 задач:

```sh
.venv/bin/python -m baf.run --mode real   --model-evidence .local/model-evidence.json
```

Каждая команда выше делает платные запросы. Результаты сохраняются в новом каталоге `results/baf/real/` вместе с событиями и собранными файлами. После ошибки исполнения или неподтверждённого режима/имени модели запускатель прекращает оставшиеся задачи и сохраняет `not_run`; пропущенная задача не становится успехом.

Для возвращения к автономной демонстрации установите `MODEL_MODE=mock` и примените `sh scripts/compose.sh up -d --wait`. Команда `sh scripts/check.sh` также принудительно использует имитацию и отключает внешнюю сеть, независимо от значений в `.env`.

## Как ограничиваются расходы

Реализация: [runtime/budget.py](../../runtime/budget.py) и [runtime/proxy.py](../../runtime/proxy.py).

Профиль закрепляет модель, поставщика, режим high, максимум 4096 выходных токенов и верхние цены 0,30/1,20 доллара за миллион входных/выходных токенов. Отдельная плата за запрос запрещена. Допускаются только текстовые сообщения размером до 256 КиБ и вызовы клиентских функций; автоматический переход к другому поставщику выключен.

Перед обращением к поставщику атомарно резервируются 0,35 доллара. Полный контекст 1 048 576 токенов и 4096 выходных токенов по максимальным ценам дают 0,319488 доллара; резерв содержит запас. Подтверждённая `usage.cost` при `usage.is_byok=false` списывается с округлением каждого запроса вверх до миллионной доли доллара, а неиспользованная часть резерва возвращается.

При неизвестной стоимости, неполном ответе об оплате или ошибке транспорта резерв сохраняется. Несовпадение модели/поставщика, обнаруженная внешняя оплата BYOK или стоимость выше резерва блокируют последующие вызовы. Учёт хранится в SQLite и сохраняется после перезапуска. Внутренний маршрут посредника `/budget` возвращает состояние учёта без ключей.

Граница относится к списаниям кредитов OpenRouter через этот профиль и зависит от соблюдения поставщиком опубликованных тарифов и ограничений токенов. Другие каналы оплаты и комиссия приобретения кредитов не включены. Основания: [параметры маршрутизации](https://openrouter.ai/docs/guides/routing/provider-selection), [учёт использования](https://openrouter.ai/docs/cookbook/administration/usage-accounting), [BYOK](https://openrouter.ai/docs/guides/overview/auth/byok), [ограничения запроса DeepSeek](https://api-docs.deepseek.com/api/create-chat-completion/).

## Остановка и восстановление

`docker compose down` сохраняет журнал. `docker compose down -v` удаляет том `model-state` вместе с ним. Пропавший журнал нельзя инициализировать заново с прежним бюджетом так, будто прошлых списаний не было: восстановите исходную базу из согласованной резервной копии либо сначала сверите уже понесённые расходы для нового бюджета. Копирование базы выполняется при остановленном посреднике; согласованная копия SQLite создаётся штатным механизмом backup, а не копированием одного файла из работающей базы.

[Проверка хранения](../../evidence/verification/budget-storage.json) подтверждает работу от непривилегированного пользователя, сохранение резерва после перезапуска и отказ при удалённом журнале. Платные запросы для этой проверки не требуются.

## Результат модели и учёт токенов

Клиент проверяет режим и точное имя модели до создания сессии; управляющий цикл и посредник проверяют их повторно. Клиент с режимом `mock`, подключённый к серверу `real`, завершается до вызова поставщика.

Цикл принимает завершённый текстовый ответ с `finish_reason=stop` либо непустой список инструментов с `finish_reason=tool_calls`. Усечённый или отфильтрованный ответ даёт `model_error`; его инструменты не выполняются. Доступные неотрицательные счётчики токенов сохраняются и при ошибке. Неполный учёт отмечается `tokens_complete=false`, а неизвестные суммы — `null`, не нулём. Отрицательная независимая проверка файлов сама по себе не стирает полный учёт токенов.
