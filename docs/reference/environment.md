# Среда сборки и проверки

Записанные проверки выполнены 6 ноября 2026 года на Mac с Apple Silicon и локальной виртуальной машине Linux. Модель вызывается через удалённый HTTPS-интерфейс; её веса не размещаются на Mac или в виртуальной машине.

| Компонент | Проверенная конфигурация |
| --- | --- |
| Mac | macOS 26.4.1, ARM64, 24 ГиБ памяти, 14 процессорных ядер |
| Виртуальная машина | Colima, Ubuntu 24.04.4, `aarch64`, Linux 6.8.0-117 |
| Ресурсы виртуальной машины | 4 процессорных ядра, 6 ГиБ памяти, диск 30 ГиБ |
| Docker Engine | 29.5.2 |
| Docker Compose внутри Linux | 5.1.4 |
| Python клиента | 3.12.13 |
| Базовый образ служб и песочницы | `python:3.12.12-slim-bookworm`, закреплённый версионный тег в Dockerfile |

## Предпосылки

Серверу нужен Linux Docker Engine с поддержкой ограничений cgroup v2 и Docker Compose. Менеджер песочниц получает `/var/run/docker.sock`: это доверенный административный компонент выделенной среды. Инструменты модели не получают сокет или ключ поставщика.

Первичная подготовка образов и зависимостей требует сети. Python-зависимости закреплены в [uv.lock](../../uv.lock) и [requirements.lock](../../requirements.lock), базовые образы — в [Dockerfile](../../Dockerfile) и [Dockerfile.sandbox](../../Dockerfile.sandbox). Используются образы для ARM64; перенос на другую архитектуру требует отдельной проверки.

В новом клоне:

```sh
cp .env.example .env
uv sync --frozen
docker compose up --build
```

На проверенном Mac доступна отдельная команда `docker-compose`, а плагин `docker compose` отсутствовал. Скрипт [scripts/compose.sh](../../scripts/compose.sh) выбирает доступный вариант; например, `sh scripts/compose.sh up --build`. Внутри Linux проверена каноническая команда `docker compose up --build`.

## Автономные проверки

После подготовки образов одна команда запускает проверки без сборки и скачивания образов:

```sh
sh scripts/check.sh
```

Она принудительно включает имитацию модели, очищает настройки внешнего поставщика в контейнере и отключает внешнюю сеть модельного посредника. Тестовый контейнер имеет только внутреннюю сеть проекта. Записанный результат — 244 теста и 48 проверок набора в каждой среде:

- [Mac/Docker](../../evidence/verification/checkpoint-final-mac.txt): 244 теста, 18,58 секунды.
- [Linux](../../evidence/verification/checkpoint-final-linux.txt): 244 теста, 18,83 секунды.

В обеих записях нет ошибок и пропусков; два предупреждения относятся к устаревшему обработчику запуска FastAPI. Это результаты конкретного проверенного состояния исходников, а не замеры каждого последующего изменения документации.

Linux-проверка использовала отдельное чистое дерево исходников без `.venv`, `.env` и `.git` и пустые тома проекта в подготовленной виртуальной машине. Это не установка новой операционной системы. [Проверка очистки](../../evidence/verification/checkpoint-final-cleanup.json) подтверждает отсутствие контейнеров, включая остановленные, песочниц, сетей и томов изолированного тестового проекта.

## Монтирование

Отдельный прототип использует SSHFS 3.7.6 на Linux и AsyncSSH 2.24.1 на Mac. SSHFS собирается отдельно от системного пакета. macFUSE на Mac не требуется: файловая система монтируется на Linux. Предпосылки, команды подготовки и удаления временных ресурсов описаны в [руководстве прототипа](../../prototypes/mounting/README.md), результаты и ограничения — в [сравнении вариантов](mounting.md).

## Остановка

```sh
docker compose down
```

Обычная остановка сохраняет именованные тома, включая журнал расходов. `down -v` удаляет эти данные и подходит только для одноразовой тестовой среды либо после сохранения и сверки постоянного состояния. Удаление журнала не отменяет расходы предыдущих вызовов; правила восстановления описаны в [руководстве модели](model.md).
